# Architecture Decision Records (ADRs)

ADRs record proposed, active, and historical technical decisions that shape the system beyond a single implementation detail — context, tradeoffs, consequences, and rejected alternatives. Use [`../../templates/adr.md`](../../templates/adr.md) to start a new one.

Only ADRs with `status: Accepted` are current guidance. Architectural decisions are human-owned; an agent can help draft ADR text from an accepted decision, but the decision itself is not the agent's to make.

## Status values

- `Proposed` — under discussion, not yet current guidance.
- `Accepted` — the current decision.
- `Superseded` — replaced by a newer ADR (link it via `superseded_by`).
- `Deprecated` — discouraged but still relevant historically.
- `Rejected` — considered but intentionally not adopted.

When a decision changes, create a new ADR and mark the old one `Superseded` rather than rewriting it.
